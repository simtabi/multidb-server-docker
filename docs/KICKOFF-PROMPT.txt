VERIFIED RESEARCH BASELINE. The following facts were already confirmed against
sources during spec design. Treat them as settled: verify currency and exact
versions, do not re-litigate the conclusions.
- Postgres data directories are major-version-specific; changing the image
  major on an existing volume fails ("database files are incompatible with
  server"); minor bumps are safe. Hence per-engine per-major volumes.
  (github.com/docker-library/postgres/issues/37)
- PG 18+ images store data in major-versioned subdirs and expect the mount at
  /var/lib/postgresql (not .../data) so pg_upgrade --link works.
  (github.com/docker-library/postgres/issues/1377)
- Base the PG image on pgvector/pgvector (official, tags per PG major, built
  via PG_MAJOR build arg). Parallel HNSW builds need shm-size at least
  maintenance_work_mem. (github.com/pgvector/pgvector)
- The official image entrypoints own first-run init, POSTGRES_*/MYSQL_* envs,
  the _FILE secret convention, and /docker-entrypoint-initdb.d. s6-overlay
  wraps and invokes them as the supervised service; it never replaces them.
  (hub.docker.com/_/postgres, _/mysql, _/mariadb)
- Multi-DB provisioning uses the database:username:password triplet format
  (vendored script; pattern from danielptv/postgres-multiple-databases,
  mechanism from mrts/docker-postgresql-multiple-databases; initdb.d works
  identically on mysql and mariadb images).
- tiredofit/docker-db-backup natively covers postgres, mysql, and mariadb with
  per-job DBnn_ config, S3-compatible targets, compression, encryption,
  checksums, notifications, and restore helpers. One dump helper script is
  shared by sidecar jobs and make targets so flags never drift.
- mysqldump defaults include triggers but EXCLUDE stored routines and events;
  a complete dump requires --single-transaction --routines --triggers
  --events --quick. Per-DB pg_dump misses roles/grants; run
  pg_dumpall --globals-only alongside every backup run.
- Cert hot-reload differs: MySQL uses ALTER INSTANCE RELOAD TLS, MariaDB uses
  FLUSH SSL. require_secure_transport works on MariaDB 10.5+ and secure
  transports include unix sockets, so sockets survive prod TLS enforcement.
  MySQL 8.4+ drops mysql_native_password by default (compat toggle needed).
- Unix sockets are shared between containers via a named volume holding the
  socket dir; host-to-container sockets work only on native Linux (Docker
  Desktop's VM blocks it on macOS/Windows; hosts there use loopback TCP).
- One service per container is Docker's own guidance; multi-daemon containers
  break lifecycle/healthchecks and interleave stdout into unparsable logs.
  s6-overlay supervision is legitimate only for a single engine plus its own
  helpers (linuxserver.io pattern). Sail and DDEV both isolate databases as
  separate containers. (docs.docker.com multi-service_container)
- phpMyAdmin's official image serves multiple servers via PMA_HOSTS (comma
  list), PMA_ARBITRARY for ad-hoc, PMA_SSLS for per-host TLS. Adminer speaks
  all three engines. pgAdmin pre-provisions via a mounted servers.json.
- Caddy provides automatic HTTPS: internal CA in dev (*.localhost resolves to
  127.0.0.1 natively), Let's Encrypt in prod, basic auth on UI routes.
- Postgres has no built-in automatic failover; the standard HA stack is
  Patroni (leader election via etcd) + HAProxy routing writes/reads through
  Patroni's REST health checks (/primary, /replica; one write port, one read
  port) + pgBouncer per node + pgBackRest shared repo. libpq multi-host with
  target_session_attrs=read-write is the client fallback. ~500 direct PG
  connections cost roughly 5GB, which is why pooling is mandatory in prod.
  A single HAProxy or pgBouncer container is itself a SPOF; note mitigations.
- Security baseline: pinned digests, secrets only via _FILE/docker secrets,
  internal networks with nothing published by default, hostssl-only pg_hba,
  non-root, cap_drop ALL, no-new-privileges, resource limits, and the
  Tailscale sidecar pattern (network_mode: service:ts) for private prod access.
